How we build and scale CrossQ

Solo developer, React Native on both platforms, required accounts, planned for 1M+ users across both borders. The core insight that makes this cheap: wait data is identical for every user — only ~150 ports exist, so almost everything is cacheable. ← Integration spec · Prototype

2 · Architecture — why 1M users is cheap here

Read path scales for free. ~150 ports × waits + forecasts fits in one ~200 KB Redis blob rebuilt every poll. The API serves it with ETag + 30 s CDN cache — 1M users generate cache hits, not database queries. Zero per-user compute on the hot path.
Drive ETAs stay client-cheap. The app sends one coarse location (rounded to ~1 km); the server batches a Routes matrix call for nearby ports and caches it 2 min per grid cell — so 10k users in San Diego share the same matrix result.

Versioned under /v1; additive changes only within a version. Public reads stay unauthenticated so the CDN can cache them for everyone.

5 · Prediction model

Features. Hour-of-day × day-of-week, US/MX/CA holiday flags (and school-break calendars), lanes_open, rolling 1/4/24 h wait averages, same-hour-last-week, port fixed effects. One quantile LightGBM per horizon bucket (0–3 h, 3–12 h) predicting P20/P50/P80 — quantiles give the UI its honest ± range for free.
Ops. Nightly retrain on the Timescale archive (minutes on one box), writes forecasts rows, bumps model_version. A blend layer nudges the next 2 h toward the live feed when it diverges. Backtest gate: new model ships only if P50 MAE beats current on the last 28 days. Cold-start ports fall back to hour×weekday medians.

6 · Alerts rules engine

AlertTriggerGuardrails
Wait spikePort wait crosses user threshold OR jumps >20 min between polls90-min dedupe; quiet hours; only for watched ports
Time to leaveTrip's re-solved leave_by enters the next 15 min, or slips >10 min from last notified valueMax 2 corrections per trip; silent after departure confirmed
ClosureFeed reports lane/port closed or CBSA planned-closure window startsFires once per closure event id
Mid-route rerouteActive trip + a sibling port's total beats current choice by >15 minRequires live-activity opt-in; max 1 per trip

The engine runs after each ingest tick: diff new snapshot vs previous, join against alert_rules, enqueue matches to BullMQ, workers fan out to APNs/FCM. Everything evaluated server-side — the app never needs background polling.

7 · Caching & cost control

Cache ladder. Device (MMKV, stale-while-revalidate) → CDN (30 s for /waits, 1 h for /forecast, 24 h for /ports) → Redis snapshot → Postgres. A user opening the app typically touches only the first two layers.
The only scary bill is Google Routes. Grid-cell ETA sharing (§2) caps calls at ~(active grid cells × nearby ports / 2 min), independent of user count. Budget alarm at $50/day; degrade path: fall back to great-circle-distance × historical speed and label ETAs "approx".

8 · Auth, security & offline

Auth. Sign in with Apple + Google via managed provider; short-lived JWTs, refresh in secure storage (Keychain/Keystore). Location never stored server-side beyond the rounded grid cell of the last ETA request; trips store the port, not your house. Rate limits per token; account deletion is one endpoint, cascades everything.
Offline. Border zones have terrible cell coverage — the app must degrade honestly: last snapshot + forecasts persist in MMKV, every number shows its age ("as of 12 min ago"), the ESTIMATED badge appears past 30 min, and leave-by times freeze with a stale banner rather than silently drifting. Port directory ships in the bundle so first launch works offline.

9 · Deploy, CI/CD & monitoring

Ship path. Monorepo (app + api + model). GitHub Actions: typecheck/test → deploy API to Fly (blue-green) → EAS build on release tags; JS-only fixes go out same-day as OTA updates, native changes ride store review. Staging env polls the same public feeds (they're free).
Feed health is THE metric. Grafana panels: per-source feed age, parse failures, ports reporting, alert queue depth, Routes spend. Page (solo dev: phone push) when a feed is >45 min stale or parse errors spike — the product's honesty features (§8) are the user-facing half of this same system.

WEEKS 1–2Ingest first. Pollers + schema + Redis snapshot. Start archiving history NOW — the model is only as good as the archive is long.
WEEKS 3–5App core. RN app: home ranking, port detail, map. Reads only /waits + /etas; forecasts show hour×weekday medians until the model has data.
WEEKS 6–7Accounts + trips + alerts. Auth, trip solver, rules engine, push. This is the retention layer.
WEEK 8+Model + polish + ship. LightGBM once ≥6 weeks of archive exists; offline hardening; store review. TestFlight/Play beta from week 5.
